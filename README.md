# AI Букет — клікабельний прототип

Прототип Telegram Mini App для генерації букетів з наявних квітів. Без стилю, замість фото — заглушки.

## Як запустити

Потрібен Node.js 20 або новіший (https://nodejs.org).

1. Відкрийте термінал у цій папці (там, де лежить `package.json`).
2. Встановіть залежності (один раз):

   ```
   npm install
   ```

3. Запустіть:

   ```
   npm run dev
   ```

4. Відкрийте в браузері http://localhost:3000

## Що в прототипі

- **Перемикач ролі вгорі** — лише для прототипу: «Клієнт» або «Працівник студії».
- **Клієнт:** каталог (пошук, залишки, ліміти) → формат → генерація → результат з історією варіантів для цього складу → надіслати студії / поділитися / зберегти.
- **Працівник:** те саме без ліміту генерацій + «Адмінка»: каталог (додавання квітки з кількістю, зміна залишку, показ/приховування), стиль (референсні фото), налаштування лімітів, статистика.

Усі зміни в адмінці одразу впливають на клієнтську частину. Дані живуть лише до перезавантаження сторінки.

## Як влаштований код

```
app/
  page.jsx                  — точка входу, лише підключає прототип
  components/
    Prototype.jsx           — каркас: стан клієнтського флоу, шапка, роздає дані екранам
    ui.jsx                  — іконки, кнопки, перемикач, нижня шторка, картка вибору
    ShareDialog.jsx         — імітація вікна «Поділитися» в Telegram
    AdminSheets.jsx         — шторки адмінки (нова квітка, зміна категорії, новий варіант формату)
    CategoryPicker.jsx      — вибір / створення / видалення категорії
  screens/                  — екрани клієнта: каталог, формат, генерація, результат, ліміт
    admin/                  — адмінка: каталог, формат, стиль, налаштування, статистика
  hooks/
    useStudioData.js        — ДАНІ студії (квітки, категорії, формати, налаштування) і дії над ними
    useAdminUi.js           — стан інтерфейсу адмінки (відкриті шторки, чернетки форм)
  lib/
    data.js                 — початкові дані прототипу
    utils.js                — чисті допоміжні функції (множина, розмір букета, вибір формату)
```

**Головне правило:** екрани не знають, звідки беруться дані. Усе читання й запис даних студії
проходить через `hooks/useStudioData.js`. Коли підключимо базу (Supabase), міняється цей файл, а екрани
лишаються як є.

## Передача проєкту

- Налаштування й ключі: див. `.env.example`. Реальні ключі в репозиторій не додаємо: у проді вони лежать
  у налаштуваннях Vercel (Settings → Environment Variables).
- План розвитку, рішення й відкриті питання — у `CLAUDE.md`.

## Сервер і база

- **Вхід:** `Authorization: tma <initData>` від Telegram, підпис перевіряється в `app/lib/server/telegramAuth.js`.
- **Маршрути:** `app/api/bootstrap` (старт), `app/api/admin/*` (зміни, лише працівник), `app/api/admin/team` (лише власник), `app/api/health` (перевірка налаштувань).
- **Змінні середовища:** див. `.env.example`. На Vercel додаються в Settings → Environment Variables.
- **База:** виконати по черзі `supabase/migrations/0001_init.sql` і `0003_generations.sql` у Supabase (SQL Editor), по одному разу (`0002` це необов'язкові демо-дані). Власник додається вручну:
  `insert into public.app_users (telegram_id, first_name, role) values (<ВАШ_TELEGRAM_ID>, 'Власник', 'owner');`
- **Локально без Telegram:** у `.env.local` задати `NEXT_PUBLIC_DEV_TELEGRAM_ID`; вгорі з'явиться перемикач ролі (лише в режимі розробки).
- **Чат студії:** `STUDIO_CHAT_ID` (номер групи, куди бот надсилає варіанти). Бота потрібно додати в цей чат.
- **Модель зображень:** поки заглушка, див. `app/lib/server/imageGen.js`.
